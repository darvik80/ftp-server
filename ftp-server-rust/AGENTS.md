# Правила подпроекта `ftp-server-rust`

Роль агента и режим ответов задаёт корневой [AGENTS.md](../AGENTS.md). Здесь — только специфика Rust.

## Стек и запуск

- Edition 2024 (нужен `rustc` ≥ 1.85). На этой машине Rust-тулчейн не установлен — `cargo` отсутствует.
- После установки: `cargo run`. Порт/корень — `FTP_PORT`, `FTP_ROOT`.
- `[dependencies]` пуст: каркас собирается без сети и без загрузки crates.

## Структура

- `Cargo.toml` — пакет `ftp-server-rust` 0.1.0, без зависимостей.
- `src/main.rs` — читает переменные окружения, печатает scope шага 1. Протокола нет.

## Конвенции

- Асинхронный рантайм и выбор crate решать при начале шага 1, а не «на всякий случай»: две TCP-сессии на сессию FTP — это то место, где модель исполнения действительно видна.
- Значения порта и каталога читать из окружения одним местом, конфигурационный тип держать отдельно от кода протокола (аналог `internal/config` в Go).
- Ошибку поднимать `Result` вверх по стеку, коды ответов RFC 959 — отдельный тип, а не `String` в точки вызова.
- `unsafe` в сетевом коде не нужен; если появляется — это аргумент, что выбранное решение стоит пересмотреть.

## Область реализации

Шаг 1 — [RFC 959](../docs/rfc-959.md), [RFC 1123](../docs/rfc-1123.md), [RFC 854](../docs/rfc-854.md); чек-лист — [../docs/kb/requirements.md](../docs/kb/requirements.md).
