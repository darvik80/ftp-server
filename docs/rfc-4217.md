# RFC 4217 — Защита FTP с помощью TLS

**Оригинал (англ.):** Securing FTP with TLS  
**Статус:** Proposed Standard  
**Год:** 2005  
**Авторы:** P. Ford-Hutchinson  
**Приоритет реализации:** 9 — Высокий приоритет  
**Официальный текст:** <https://www.rfc-editor.org/rfc/rfc4217.html>

## Аннотация

Конкретный профиль RFC 2228 для TLS: FTPS (explicit). Закрывает проблему перехвата паролей и данных. Для продакшена — следующий после базовой функциональности приоритет.

## Абстракт (перевод)

Документ описывает механизм, с помощью которого FTP-клиенты и серверы могут реализовать безопасность и аутентификацию через TLS (RFC 2246) и расширения RFC 2228. Определяет необходимое подмножество расширений, параметры, политические вопросы и ожидаемое поведение для совместимости.

## Ключевые положения

### Типичный сценарий (explicit FTPS)

1. Клиент подключается к порту 21 (открытый текст).
2. `AUTH TLS` → сервер отвечает 234 и выполняет TLS handshake на управляющем канале.
3. `USER` / `PASS` уже внутри TLS.
4. `PBSZ 0` и `PROT P` — защита канала данных.
5. Передачи RETR/STOR идут по TLS data connection.

### Implicit FTPS

Исторически порт 990 с немедленным TLS — не описан здесь как основной стандартный путь; на практике часто поддерживается, но RFC фокусируется на AUTH TLS.

### Политики

- Требовать ли TLS до ввода пароля.
- Разрешать ли CCC.
- Сертификаты и проверка имени хоста.

### Для реализации

После рабочего plain FTP добавьте AUTH TLS + PROT P; объявите `AUTH TLS` в FEAT.
