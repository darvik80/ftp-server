# RFC 2228 — Расширения безопасности FTP

**Оригинал (англ.):** FTP Security Extensions  
**Статус:** Proposed Standard  
**Год:** 1997  
**Авторы:** M. Horowitz, S. Lunt  
**Приоритет реализации:** 8 — Высокий приоритет  
**Официальный текст:** <https://www.rfc-editor.org/rfc/rfc2228.html>

## Аннотация

Каркас безопасного FTP: AUTH, ADAT, PROT, PBSZ, CCC, MIC/CONF/ENC. Сам по себе не привязан к TLS — это общий API безопасности. Нужен как фундамент для FTPS (RFC 4217).

## Абстракт (перевод)

Документ определяет расширения спецификации FTP (STD 9, RFC 959), обеспечивающие сильную аутентификацию, целостность и конфиденциальность управляющего и канала данных через новые необязательные команды, ответы и процедуры.

## Ключевые положения

### Новые команды

| Команда | Назначение |
|---------|------------|
| AUTH | Выбор механизма безопасности (например, TLS) |
| ADAT | Обмен данными аутентификации |
| PBSZ | Размер буфера защиты |
| PROT | Уровень защиты канала данных (C/S/E/P) |
| CCC | Clear Command Channel — снять защиту с управления |
| MIC / CONF / ENC | Целостность / конфиденциальность команд |

### Новые коды

Включая 234/334 для AUTH, 235/335 для ADAT, 431, 533–537 и др.

### Для реализации

Не реализуйте «в вакууме»: используйте вместе с RFC 4217 (TLS). Минимум для FTPS: AUTH TLS, PBSZ 0, PROT P.
