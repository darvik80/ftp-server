# RFC 1123 — Требования к интернет-хостам — приложения и поддержка

**Оригинал (англ.):** Requirements for Internet Hosts — Application and Support  
**Статус:** Internet Standard  
**Год:** 1989  
**Авторы:** R. Braden  
**Приоритет реализации:** 2 — Критично  
**Официальный текст:** <https://www.rfc-editor.org/rfc/rfc1123.html>

## Аннотация

Уточняет и ужесточает требования RFC 959 для реальных хостов: обязательные команды, поведение PASV/PORT, обработка многоадресных имён, тайм-ауты, безопасность. Без этих требований сервер будет «по бумаге RFC 959», но плохо совместим с практикой.

## Абстракт (перевод)

Документ является одним из документов семейства «требования к интернет-хостам». В разделе, посвящённом FTP, формулируются обязательные (MUST), рекомендуемые (SHOULD) и необязательные требования к клиентам и серверам FTP, уточняющие RFC 959 на основе опыта эксплуатации.

## Ключевые положения

### Зачем нужен при реализации сервера

RFC 1123 (STD 3) — это «обязательный чеклист» поверх RFC 959. Многие клиенты ожидают именно поведение из 1123, а не «чистый» 959 1985 года.

### Ключевые требования к FTP-серверу

- Поддерживать **TYPE A** и **TYPE I** (IMAGE/binary).
- Поддерживать **MODE S** (STREAM) как минимум.
- Реализовать **PASV** (для работы через firewall/NAT это критично).
- Корректно обрабатывать **многоадресные** (multihomed) хосты.
- Не использовать FTP MAIL-команды как основной почтовый транспорт (историческое ограничение).
- Тайм-ауты на управляющем соединении; корректный ответ на неожиданные команды.
- LIST и NLST должны работать предсказуемо; формат LIST не стандартизирован жёстко (отсюда позже MLST в RFC 3659).
- Рекомендации по безопасности: не раскрывать лишнее в баннерах, осторожность с анонимным доступом.

### Практический вывод

После RFC 959 сразу закрывайте требования RFC 1123 — это второй обязательный слой совместимости.
