# RFC 2389 — Механизм согласования возможностей FTP

**Оригинал (англ.):** Feature negotiation mechanism for the File Transfer Protocol  
**Статус:** Proposed Standard  
**Год:** 1998  
**Авторы:** P. Hethmon, R. Elz  
**Приоритет реализации:** 3 — Критично  
**Официальный текст:** <https://www.rfc-editor.org/rfc/rfc2389.html>

## Аннотация

Вводит FEAT и OPTS. Современные клиенты (FileZilla, lftp, curl) сначала спрашивают FEAT, чтобы узнать SIZE/MDTM/UTF8/AUTH TLS и т.д. Без FEAT расширения «невидимы» и часто не используются.

## Абстракт (перевод)

Документ предоставляет механизм, с помощью которого клиенты FTP могут узнать, какие новые возможности поддерживает конкретный FTP-сервер.

## Ключевые положения

### Проблема

RFC 959 не предусматривал стандартного способа узнать, какие расширения поддерживает сервер. Клиенты угадывали методом проб и ошибок.

### Решение

#### FEAT
Команда без аргументов. Ответ — многострочный список возможностей:

```
211-Features:
 AUTH TLS
 EPSV
 MDTM
 PASV
 REST STREAM
 SIZE
 TVFS
 UTF8
211 End
```

#### OPTS
`OPTS <feature> [options]` — настройка параметра расширения (например, `OPTS UTF8 ON`, `OPTS MLST ...`).

### Для реализации

Реализуйте FEAT сразу после базового RFC 959/1123 — это «витрина» всех последующих расширений.

## Что реализовать

- [ ] Команда FEAT
- [ ] Команда OPTS
- [ ] Формат многострочного ответа 211
